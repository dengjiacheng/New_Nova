# 治理路线

## 指标体系

- **可靠性**：Agent 在线率 ≥ 99%，任务成功率 ≥ 97%，脚本平均时长 ≤ 120s。
- **质量**：多端测试覆盖率 ≥ 75%，关键路径端到端测试完成率 ≥ 95%，缺陷逃逸率 ≤ 0.5/迭代。
- **交付效率**：DCP → Code PR median ≤ 2 天，需求完成 lead time ≤ 7 天。
- **安全**：高危漏洞修复 72h 内完成，季度安全评估覆盖 100% 对外接口。

## 季度治理节奏

| 月份区间 | 重点事项 | 产出 |
| -------- | -------- | ---- |
| Q1 月初 | 依赖升级、协议审视、风险矩阵复盘 | 依赖评估报告、升级计划 |
| Q1 月中 | 功能迭代、测试补强、观测指标校准 | 迭代计划、测试白名单 |
| Q1 尾部 | 发布评审、回归、指标复盘 | 发布清单、指标公报 |

> 按季度循环复用，Q2/Q3/Q4 根据业务重点调整。

## 组织分工

- **平台技术负责人**：维持架构、审查 DCP、统筹跨端技术资产。
- **后端负责人**：维护 NovaServer、数据库策略、安全合规。
- **客户端负责人**：负责 NovaAgent/NovaDesk 协同与发布。
- **SRE/QA 团队**：保障测试基线、CI/CD、观测平台。

## 治理守则

1. 所有变更先更新 DCP/Reference，再进入开发；
2. 模块级 PR 必须附带测试与风险评估；
3. 每月 1 次自动化演练（守护脚本、灾备切换）；
4. 安全审计与依赖扫描纳入 CI，失败阻断合并。
