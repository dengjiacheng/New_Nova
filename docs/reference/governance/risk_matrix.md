# 风险矩阵

| 分类 | 风险 | 可能性 | 影响 | 监控指标 | 缓解措施 |
| ---- | ---- | ------ | ---- | -------- | -------- |
| 架构 | 跨端协议不一致导致数据损坏 | 中 | 高 | 合同版本校验失败率 | 建立版本字段与兼容策略，变更需评审 |
| 架构 | Worker 队列堵塞影响执行 | 低 | 高 | 队列积压长度、处理延迟 | 引入队列监控与自动扩容阈值 |
| 质量 | 测试覆盖不足导致回归 | 中 | 高 | 覆盖率、缺陷逃逸 | 守护检测覆盖率，阻断低于阈值 PR |
| 运维 | 依赖安全漏洞 | 中 | 高 | CVE 通告、`npm audit`/`pip-audit` 结果 | 建立季度升级窗口与紧急响应流程 |
| 客户端 | Agent 离线率高 | 中 | 高 | 在线率、心跳延迟 | 增强断线重连与离线任务缓存 |
| 数据 | 配置泄露 | 低 | 高 | 配置仓访问审计 | 使用 Secret 管理服务，启用最小权限 |
| 合规 | 日志含敏感数据 | 中 | 中 | 隐私审计结果 | 引入日志脱敏过滤器，定期审查 |
| 交付 | 守护/自动化失效 | 低 | 中 | 守护任务失败告警 | 引入心跳报警、手动应急剧本 |

## 跟踪机制

- 风险每月评审一次，结合迭代复盘更新矩阵；
- 建立 `docs/reference/governance/risk_log.md` 记录事件、缓解执行情况；
- 将关键指标接入观测平台并设置阈值告警。
