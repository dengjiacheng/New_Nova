# 角色与权限

平台采用三角色模型，权限写死在代码配置中（后续可扩展）。

## 角色定义

| 角色 | 面向对象 | 权限范围 |
| --- | --- | --- |
| `SUPER_ADMIN` | 平台运营人员 | 管理租户、创建管理员、充值、查看全局审计、脚本目录维护 |
| `ADMIN` | 租户管理员 | 管理本租户用户、查看并管理脚本执行、发起执行、查看消费记录 |
| `USER` | 普通用户 | 查看已购脚本、创建本地模板、发起脚本执行、查看个人执行记录 |

## 权限表

| 功能 | SUPER_ADMIN | ADMIN | USER |
| --- | --- | --- | --- |
| 登录 PC/调用 API | ✔ | ✔ | ✔ |
| 管理租户/充值 | ✔ | ✖ | ✖ |
| 管理租户用户 | ✔ | ✔ | ✖ |
| 查看全局审计 | ✔ | ✖ | ✖ |
| 查看租户审计 | ✔ | ✔ | ✖ |
| 查看消费记录 | ✔ | ✔ | 查看个人 |
| 购买脚本 | ✔ | ✔ | ✔（需授权） |
| 发起脚本执行 | ✔ | ✔ | ✔ |
| 管理设备（本地 ADB） | ✔ | ✔ | ✔ |
| 管理员工具（Agent 包上传） | ✔ | ✔ | ✖ |

## 实现建议

- 在 Server 中定义权限常量：
  ```python
  class Permissions(Enum):
      VIEW_TENANT = "view_tenant"
      MANAGE_TENANT = "manage_tenant"
      VIEW_AUDIT = "view_audit"
      ...
  ```
- 角色到权限的映射写入配置：
  ```python
  ROLE_PERMISSIONS = {
      Role.SUPER_ADMIN: {...},
      Role.ADMIN: {...},
      Role.USER: {...},
  }
  ```
- JWT payload 包含 `role`，请求进入 API 前检查权限。
- PC 客户端根据角色隐藏不允许的功能入口。
- Admin 工具模块仅对 `ADMIN` 及 `SUPER_ADMIN` 展示，PC 端需在路由/侧边栏层面根据权限开关入口。

## 审计要求

- 权限变更、角色分配需写入审计日志（`action = ROLE_UPDATE`）。
- 超级管理员登录需多因素认证（建议后续实现）。

## 扩展

- 若未来需要自定义角色，可在数据库新增 `roles`、`role_permissions` 表，允许管理员在模板基础上添加/移除权限。
- 由于当前需求简单，暂不实现自定义功能。
